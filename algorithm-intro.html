尖端融合是传统方法的致命弱点

当两个角果尖端相互交叉时，骨架算法会将两个独立的尖端"合并"成一个节点，导致漏计。 果柄法的关键洞察：即使两个角果的尖端在空间上交叉， 它们的果柄（stalk）依然分别独立地附着在主干的不同位置。 因此，在主干连接处计数（果柄）比在末端计数（尖端）更鲁棒。

❌ 传统方案

尖端计数法

通过骨架端点（tips）计数。 当角果尖端相互交叉时，两个端点在骨架中被合并， 识别为一个端点 → 漏计 1 个角果。 在密集种植、角果相互遮挡的场景下误差明显偏大。

✅ 果柄法

果柄（根部）计数法

统计从主干向外延伸的侧边（果柄）数量。 每一根果柄在主干上独立附着，不受尖端是否融合的影响。 即使尖端完全重叠，果柄仍然是两条独立的出边 → 精确计数。

图像预处理 PRE

若图像短边小于 800px，自动以 Lanczos 插值放大至 800px， 确保骨架计算有足够像素密度。 随后去除刻度尺区域（边缘高密度条带检测）和非主体连通域。

1

二值化分割 BINARIZE

高斯模糊 → Otsu 自适应阈值 → 形态学闭运算（3×3 椭圆核，2次）桥接断裂细枝 → 膨胀+腐蚀（5×5 核）修复根部连接。 亮色植物区域对应白色二值化结果。

2

骨架提取 SKELETON

调用 skimage.morphology.skeletonize 得到 1px 宽骨架线。 骨架像素集合以 set{(r,c)} 存储， 并使用距离变换（cv2.distanceTransform）预计算每个骨架点的局部宽度， 用于后续枯枝宽度判断。

3

主干识别 MAIN STEM

用 Numba JIT 加速的 多端点评分 BFS 找主干： 枚举所有端点对，按 长度 × 直线度评分 排序，选最佳路径为主干。 内置刻度尺自动排斥：若主干均匀宽度变异系数 CV < 0.15， 判定为刻度尺并洪泛填充后重新计算，最多重试 2 次。

4

拓扑图构建 TOPO GRAPH

将非主干骨架像素按度（degree）分类为三类节点：

Attach 节点
紧邻主干的像素，即果柄的根部附着点
Tip 节点
度=1，末梢端点，对应角果尖端
Junction 节点
度≥3，骨架分叉点

相邻节点之间的度=2 像素链构成边（Edge）， 完整记录边的像素路径序列。

5

Pass 1 — 枯枝识别与过滤 PASS 1

从每个 Tip 节点出发，BFS 回溯到最近的 Attach 节点，重建完整枝路径。 对每条枝计算面积 area（路径各点宽度×2 求和）和平均宽度 avg_w。 两步自适应过滤：

  • 去噪：路径长度 < 10px 的短枝直接剔除（骨架噪声）
  • 枯枝过滤：计算剩余枝的 中位面积 和 中位宽度， 低于中位值 × 0.25（面积）或 × 0.70（宽度）的判为枯枝
  • 至少 4 条有效枝时才启用自适应过滤，避免数量不足时误删
6

Pass 2 — 清洁骨架重建 + 果柄计数 PASS 2

将 Pass 1 标记的枯枝像素从骨架中移除（保留主干）， 对清洁骨架重新构建拓扑图。 遍历所有 Attach 节点，统计其连出的非主干边数量， 每一条出边 = 1 个果柄 = 1 个角果。无需二次过滤。

7

VLM 视觉大模型复核 VLM

算法将每个果柄的尖端坐标归一化后作为 markers 输出， 交由 doubao-seed-2-0-pro 视觉大模型二次审核。 VLM 仅检查 CV 认定的有效角果（P点）中是否有枯枝误判， 置信度 ≥ 0.8 的误判点从最终计数中剔除。

枯枝过滤：自适应中位数比值法
Pass 1 / Pass 2 两阶段细节

🔍 Pass 1 — 识别枯枝

  • 对骨架上每个叶片节点（tip）做 BFS 回溯，找到它连接主干的完整路径
  • 用距离变换计算每个路径像素处的局部半径，估算枝的真实宽度
  • Area = Σ(宽度×2)：正比于枝的横截面积积分
  • avg_w = Area / 路径长度：平均粗细
  • 阈值：area_fence = median_area × 0.25、width_fence = median_width × 0.70
  • 同时满足两个下界才判为有效枝，否则标记为枯枝

✂️ Pass 2 — 清洁计数

  • 从骨架像素集合中减去 Pass 1 标记的所有枯枝像素
  • 主干像素强制保留，不受过滤影响
  • 重新调用 _build_topo_graph，在干净骨架上重建节点/边
  • 遍历 Attach 节点的邻接表，统计非主干出边 → 果柄数
  • 设 seen_edges 集合防止重复计数同一条边
  • 结果即最终角果数，无需再次宽度过滤

用标注好的参考图作为"视觉锚点"，让大模型区分枯枝与正常角果

为什么需要 Few-Shot？

纯文字描述"枯枝颜色偏暗、粗细均匀"对大模型来说是抽象的，不同拍摄条件下变化很大。 通过在每次 VLM 调用时附带标注好的枯枝正例与反例参考图， 让模型直接对比视觉特征，能显著降低误判率——这就是图像级 Few-Shot 的核心思路。

⚖️

Prompt 中的代价不对称约束

  • Few-Shot 图像之外，prompt 还显式告知模型：误删 1 个真角果 = 漏过 5 个枯枝的代价
  • 所有模糊、被遮挡、看不清的 P 点 → 一律保留，不报告
  • 置信度阈值 VLM_FP_CONFIDENCE_THRESHOLD = 0.8 可通过 .env 调整
  • VLM 返回 {"false_positives": [{"id": 3, "confidence": 0.9}]} 格式，confidence 低于阈值的自动忽略
  • 兼容旧版裸 id 列表格式（按 0.9 置信度处理）
🔧 如何扩充 Few-Shot 样本

直接向 app/support/ 目录添加新图片， 并在 pt.md 中新增一行 枯枝正例X: 描述 或 枯枝反例X: 描述。 系统启动时自动加载，无需改代码。图片格式支持 .png / .jpg / .jpeg / .bmp / .webp。

方法优势
相比传统骨架尖端计数法的改进
🔗

不受尖端融合影响

角果尖端空间交叉不影响各果柄在主干上的独立附着点，计数更准确。

🌿

自适应枯枝过滤

基于中位数的面积+宽度双重过滤，无需手动设置绝对阈值，适应不同图像分辨率和密度。

🔁

两遍设计消除污染

Pass1 标记、Pass2 在清洁骨架上重建图，避免枯枝像素残留干扰计数拓扑。

⚡

Numba JIT 加速

主干识别的多端点评分 BFS 全部用 Numba 加速，首次调用预编译后处理速度极快。

📏

刻度尺自动排除

通过均匀宽度检测，自动识别图像中的刻度尺区域并移除，无需手动裁剪。

🤖

VLM 兜底复核

CV 算法结果交视觉大模型二次确认，仅针对有效角果中的误判，用最少 token 实现误差兜底。
